# Evidence Integrity — Dataset Protocol

Status: design only; no live calls authorized. Synthetic world first; a small
human-reviewed set would be needed before any live claim.

## 1. Labeling procedure

Every example is a tuple:

```
(claim, subclaims, ground_truth_label, risk_class, required_assurance)
(evidence_items[])
  each item: {id, type, ancestry[], scope[], reliability,
              freshness, provenance_meta_status, verdict, failure_modes}
(policy_inputs)
decision_outcome_for_evaluation
```

## 2. Composition (target: ~320 labeled examples, seed-deterministic)

| Bucket | Count | Purpose |
|---|---|---|
| Known-correct claims, independent evidence | 60 | Calibration + sanity |
| Known-incorrect claims, independent evidence | 50 | False-accept measurement |
| Partially correct claims (scope mismatch) | 40 | Scope gating |
| Claims with duplicated evidence from one source | 30 | Duplicate attack |
| Claims with N sources traced to one common bad root | 40 | Shared-ancestry attack |
| Claims with unknown provenance | 30 | Unknown-dependency rule |
| Claims with contradictory evidence | 30 | Contradiction handling |
| Claims with stale evidence | 15 | Freshness gating |
| Adversarially misleading metadata (false lineage) | 15 | Fails-safe test |
| Correct claims with only one deterministic check | 10 | Cheap acceptance path |

## 3. Ground-truth generation rules

- Difficulty `D ~ U(0,1)`; correctness sampled from per-model failure curves
  (`cheap: 0.05 + 0.4·D`, `strong: 0.01 + 0.05·D`).
- Evidence families: `det-rule` (deterministic, ρ=1.0 inside scope),
  `cheap-judge`, `strong-judge`, `external-registry`, plus adversarial
  distractor family derived from one bad root.
- Shared ancestry is set at generation time, not recoverable from surface
  features — this is the point of the experiment.
- Unknown provenance is generated by dropping lineage metadata on 30% of
  examples uniformly.
- Evaluation set is drawn with `sha256`-seeded stream; IDs disjoint from
  calibration set.

## 4. Required assurance levels (risk classes)

- `low` (e.g., autocomplete): any ≥1 independent support accepted.
- `med` (e.g., refund ≤ limit): ≥2 independent clusters or 1 deterministic + 1 probabilistic.
- `high` (e.g., medical/financial action): ≥3 independent clusters or 2 deterministic + 1 probabilistic; otherwise REQUEST_MORE_EVIDENCE/INDETERMINATE.

## 5. Human annotation protocol (if pursued)

- 2 annotators + adjudicator; majority label; inter-annotator agreement reported (Cohen's κ).
- No personal/sensitive data; synthetic invoices/boilerplate claims only.
- Timed: ≤ 5 min/example; instructions emphasise *scope mismatch* and *evidence type*, not plausibility.
- Sample: ~200 examples; reserved for final confirmation, not development.

## 6. Leakage and hygiene

- Calibration and evaluation splits disjoint by construction; IDs hash-checked.
- No policy may read `ground_truth`, ancestry, or latent difficulty.
- Simulator deterministic given seed across processes (stdlib `random` seeded;
  never `hash()`).
- Any result not reproducible across two clean processes is rejected.
