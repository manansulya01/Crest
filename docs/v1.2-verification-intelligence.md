# V1.2 Verification Intelligence — Experiment Report

## 1. Research question

Can a system reduce total verification cost by allocating verification effort
based on task uncertainty and risk, without reducing task success rate?

## 2. Hypothesis

H1: Adaptive Verification (AV) achieves the same task success as "always verify
    at the highest tier" with lower total cost, by using cheaper verification
    tiers for low-uncertainty tasks.

H0: Adaptive Verification does not reduce total cost without reducing task success.

## 3. Mechanism: Value-of-Verification (VoV) controller

The VoV controller selects verification actions based on expected reduction in
decision risk per unit cost (Value of Information). Key innovation: uncertainty
estimation incorporates verifier false positive rates (residual uncertainty),
preventing premature acceptance after weak verification.

### Verification tiers
- T0 (structural, cost 0.0): JSON parse + required fields + types.
- T1 (consistency, cost 0.1): T0 + cross-field invariants.
- T2 (semantic-cheap, cost 0.5): T1 + cheap model judge (10% error rate).
- T3 (semantic-strong, cost 2.0): T1 + strong model judge (2% error rate).

### VoV decision rule
1. Run cheap model.
2. Run T0. If T0 fails → escalate to strong + T3.
3. If T0 passes, compute uncertainty = max(residual_fpr, pass_rate_uncertainty).
   - If uncertainty > threshold (0.15) and fewer than 2 verifications → run T2.
   - If T2 rejects → escalate to strong + T3.
   - If T2 accepts → accept (cost = cheap + T0 + T2).
4. If uncertainty ≤ threshold → accept after T0 (cost = cheap + T0).

## 4. Results (5 seeds × 200 eval tasks)

| Strategy | Success | Cost/Success | Cost/Task | Escalation |
|---|---|---|---|---|
| always-T0 | 0.766 | 1.31 | 1.00 | 0% |
| fixed_cascade | 0.907 | 2.59 | 2.34 | 43% |
| **vov** | **0.963** | **3.00** | **2.89** | 51% |
| always-T3 | 0.939 | 7.46 | 7.00 | 100% |

### Key findings
1. **VoV dominates always-T3**: 0.963 success vs 0.939 (+2.4pp) at 0.40x cost
   (3.00 vs 7.46). Strictly better on both quality and cost.
2. **VoV beats fixed_cascade on success**: +5.6pp (0.963 vs 0.907) at 1.16x
   cost per success (3.00 vs 2.59).
3. **VoV meets the pre-registered criterion**: ≥10% lower cost than always-T3
   (60% lower) with ≤2pp success loss (actually +2.4pp gain).
4. The key improvement over Cycle 1: uncertainty estimation uses verifier
   false positive rates (residual uncertainty), preventing premature acceptance
   after weak verification (T0 alone).

## 5. Prior art comparison

- **FrugalGPT**: Cascade with fixed verification. VoV improves by making
  verification adaptive (tier selection based on uncertainty).
- **Adaptive Computation Time (Graves)**: Allocates compute per token. VoV
  allocates verification per task.
- **Selective Classification (Geifman & El-Yaniv)**: Abstains when uncertain.
  VoV escalates verification instead of abstaining.
- **Value of Information (Howard)**: General framework. VoV instantiates it
  for verification actions.

## 6. What is genuinely distinct

VoV combines multi-tier verification with value-of-information action selection,
where the uncertainty estimate incorporates verifier reliability (false positive
rates), not just observed pass/fail rates. This prevents premature acceptance
after weak verification — a failure mode of simpler cascade approaches.

## 7. Failure conditions

- If verifier false positive rates are not calibrated, VoV may accept bad outputs.
- If the cost of T2 exceeds the savings from avoiding T3, VoV provides no benefit.
- If tasks have no observable risk signal, VoV cannot differentiate verification
  effort and degenerates to a fixed policy.

## 9. Decision

**ADVANCE (in simulation).** VoV demonstrates a genuine, measurable benefit:
- Dominates always-T3 (higher success, lower cost).
- Beats fixed cascade on success (+5.6pp).
- Meets pre-registered success criterion.

This is the first experiment where CREST's mechanism shows a clear cost-quality
trade-off advantage that is NOT circular (the uncertainty signal is based on
verifier reliability, not task features that predict failure).

## 10. Next single highest-value action

Design a live verification experiment: use the cheap model (gemini-3.5-flash-lite)
as T2 judge on a small set of tasks where the strong model's output is known
(from a previous successful run), to measure whether the T2 judge's error rate
is acceptable. If T2 works, the VoV advantage is real. If T2 is unreliable,
the mechanism fails.
