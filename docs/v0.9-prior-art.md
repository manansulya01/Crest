# Prior Art Review — LLM Routing and Cascading

## Relevant work

### FrugalGPT (Chen et al., 2023, ICLR 2024)
- **Mechanism:** LLM cascade. Tries the cheapest model first; if a scorer/verifier
  rejects the answer, escalates to the next model. Learns a threshold per query
  type from calibration data.
- **Results:** 50–98% cost reduction while matching the best individual model's
  accuracy; or +4% accuracy at the same cost.
- **Relevance to CREST:** Directly comparable. FrugalGPT's cascade is a
  verification-driven escalation, which is simpler and more robust than CREST's
  pre-routing (calibration-based admission). FrugalGPT does not require predicting
  failure from task features; it verifies the cheap model's output at runtime.

### Hybrid LLM (ICLR 2024)
- **Mechanism:** Quality-aware query routing. Trains a router to classify queries
  as "easy" or "hard" and routes accordingly.
- **Results:** 22% fewer calls to the expensive model with 1% quality drop.
- **Relevance to CREST:** Similar to CREST's pre-routing approach. Requires
  labeled training data. CREST's Wilson-bound admission is more conservative
  (refuses to route when evidence is insufficient) but also less flexible.

### RouteNLP (2026)
- **Mechanism:** Closed-loop LLM routing with conformal cascading. Uses conformal
  prediction for routing decisions with statistical guarantees.
- **Relevance to CREST:** The conformal approach is more principled than CREST's
  Wilson bound for small samples. CREST could adopt conformal prediction as an
  alternative admission rule.

## Implications for CREST

1. **Routing alone is not novel.** FrugalGPT, Hybrid LLM, and RouteNLP all
   demonstrate LLM routing/cascading with published results. CREST's
   contribution, if any, must be in a different dimension.

2. **Cascade > pre-routing for imperfect features.** FrugalGPT's cascade
   verifies the cheap model's output at runtime, avoiding the need for accurate
   failure prediction. CREST's pre-routing requires accurate failure prediction
   from task features, which is harder and more brittle.

3. **CREST's potential differentiation:** The verification/budget/constraint
   enforcement layer. FrugalGPT optimizes cost-quality; CREST could add explicit
   budget caps, latency constraints, privacy constraints, and auditable evidence
   trails. This is a product/infrastructure differentiation, not an algorithmic
   novelty claim.

4. **Honest assessment:** CREST's current value proposition is closer to
   "auditable inference control plane with conservative admission" than to
   "novel routing algorithm." The fake-mode 50% advantage is circular (the
   routing feature perfectly predicts the failure mode). A cascade approach
   would be more defensible but is not yet implemented or tested.

## Recommended next experiment

Implement a **cascade strategy** (try cheap → verify → escalate) and compare it
against pre-routing (CREST) and the baselines. If the cascade outperforms
pre-routing on the same workload, the product should pivot to verification-driven
escalation as the primary mechanism, with pre-routing as an optional optimization.
