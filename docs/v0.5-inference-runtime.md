# Crest V0.5 Model-Inference Runtime

Status: implemented as a separate control plane. It is not validated by the V0.4
recovery experiments or by the V0.5 Phase A recovery-admission result.

## Scope

`src/crest/inference.py` adds a small model-inference runtime with:

- `ModelAdapter`, a provider-agnostic completion protocol.
- `FakeModelAdapter`, a deterministic adapter with no network I/O.
- `HttpChatAdapter`, an OpenAI-compatible transport. Live-provider calls are
  unverified.
- `InferencePolicy`, with model allowlists, token and character limits, timeout,
  and an abstract cost-unit budget.
- `InferenceRuntime`, which validates requests, reserves budget atomically,
  calls the adapter, validates responses, records an append-only ledger, and
  fails closed on every error.
- `Store` schema v3, with `inference_requests` for reservation, usage, status,
  and a response digest.

The runtime does not reuse recovery evidence, receipts, or capability admission
as authority for model calls. Phase A validated a synthetic filesystem
recovery-admission policy; it provides no evidence about model inference.

## Budget semantics

Cost is measured in abstract cost units, not money:

```
cost_units = input_tokens * input_token_weight + output_tokens * output_token_weight
```

The runtime reserves the worst case (`max_input_tokens + request max_output_tokens`)
before calling the adapter. Reservations are never refunded. This is conservative
and follows the V0.4 rule that successful recovery does not refund exposure.

## At-most-once execution

`Store.try_begin_inference` uses `BEGIN IMMEDIATE` and a primary-key reservation
row. A duplicate `request_id` is rejected forever, including after a crash. The
ledger stores usage and a response digest, but never prompt or response text.

## Response validation

A response is accepted only when:
- request and response IDs match;
- the response model equals the requested model;
- usage is present and non-negative;
- input and output token counts are within policy and request limits;
- response text is within `max_output_chars`;
- non-empty output is present when required;
- the finish reason is in `allowed_finish_reasons`.

If validation fails, the request is marked `INVALID` and the reservation remains
charged.

## Adapter boundary

`FakeModelAdapter` is deterministic and is the only adapter exercised by tests.
`HttpChatAdapter` performs real network I/O and has no live-provider test. Do not
claim provider correctness, latency, or pricing from this repository.

## Configuration

`crest.yaml` may contain an `inference:` section. `CrestConfig.inference_policy`
loads it, and `default_yaml()` emits safe defaults. Unknown sections are still
rejected.
