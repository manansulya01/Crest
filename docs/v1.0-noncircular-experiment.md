# V1.0 Non-Circular Experiment — Preregistered Protocol

Status: PRE-REGISTERED (written before any comparative result for this experiment).

## 1. Objective

Determine whether CREST's admission and routing mechanism creates value when the
routing feature is only an imperfect predictor of the latent difficulty that
drives cheap-model failures.

This experiment is a **falsification test**. Its purpose is to decide whether
CREST should continue investing in routing, pivot to verification/constrained
execution, or stop investing in the current hypothesis.

## 2. Hypotheses

- **H0 (null):** CREST admission policy does not achieve lower cost-per-successful-task
  than the simple cost-aware baseline at comparable success rates, across all
  signal strengths and seeds.
- **H1 (alternative):** CREST admission policy achieves ≥10% lower
  cost-per-successful-task than the simple cost-aware baseline at comparable
  success (≤2pp difference) under at least one signal-strength condition with
  ≥50 calibration examples per capability class.

## 3. Simulator Design

### 3.1 Task generation

Each task has:
- **Observed features** (available to routing): `feature_a` (binary), `feature_b`
  (binary), `text_length_bucket` (low/med/high). Derived from a latent
  `difficulty_score` with controlled noise.
- **Latent difficulty** `d ∈ [0,1]`: determines failure probability. Hidden from
  all deployable strategies. Used only by the oracle and the data generator.
- **Truth**: ground-truth answer. Used only by the evaluator. Never exposed to routing.
- **Task ID**: unique identifier.

### 3.2 Feature-difficulty relationship

`d = sigmoid(signal_strength * (z_feature + noise))` where:
- `z_feature` is a standard normal derived from observed features.
- `noise ~ N(0, (1 - signal_strength)^2 + 0.1)` adds irreducible noise.
- `signal_strength ∈ {0.0, 0.2, 0.5, 0.8, 1.0}` controls predictability.

At signal=0: features are independent of difficulty (no predictive signal).
At signal=1: features perfectly predict difficulty (unrealistic upper bound).

### 3.3 Model outcomes

- Cheap model failure prob: `p_fail_cheap = 0.05 + 0.4 * d + 0.1 * (1 - signal_strength)`.
  (Harder tasks fail more; noise makes prediction imperfect.)
- Strong model failure prob: `p_fail_strong = 0.01 + 0.05 * d`.
  (Strong model is more reliable but not perfect.)
- Outcomes are Bernoulli draws seeded by (task_id, model, seed).

### 3.4 Cost model

- Cheap model: 1.0 cost unit per task.
- Strong model: 5.0 cost units per task.
- Verification: 0.1 cost units per task (structural check, always applied).
- Total cost = model cost + verification cost.

### 3.5 Strategies

1. **Fixed cheap:** always use cheap model.
2. **Fixed strong:** always use strong model.
3. **Simple cost-aware:** route to cheap if `feature_a == 0` (simple heuristic
   on observed feature), else strong. (No calibration, no admission.)
4. **CREST (existing):** calibrate on calibration set; admit cheap model per
   capability class if Wilson upper bound ≤ 0.05; route admitted classes to cheap,
   others to strong. Capability class = `feature_a` value (binary).
5. **Oracle (diagnostic only):** route to cheap if `d < 0.5`, else strong.
   Uses latent difficulty. Never deployable. Reported separately.

### 3.6 Evaluation

- Calibration set: 100 tasks (used for CREST admission).
- Evaluation set: 200 tasks (held out, never used for calibration).
- 5 random seeds: 42, 123, 456, 789, 1024.
- 5 signal strengths: 0.0, 0.2, 0.5, 0.8, 1.0.
- Total: 5 × 5 × 200 = 5000 evaluation tasks.

### 3.7 Metrics

- **Task success rate** (with Wilson 95% CI).
- **Cost per successful task** = total cost / number of successes.
- **Average cost per task**.
- **Escalation rate** (fraction routed to strong).
- **Calibration sample requirement** (min n for admission).
- **Budget violations** (none expected in simulation).

### 3.8 Uncertainty

Wilson 95% confidence intervals on success rates. Bootstrap 95% CIs (1000
resamples) on cost-per-success. Report mean ± std across seeds.

### 3.9 Stopping rules

- If CREST never beats cost-aware at any signal strength across all seeds →
  routing hypothesis not supported by this evidence.
- If CREST only wins at signal=1.0 (perfect prediction) → not realistic.
- If oracle advantage >> CREST advantage → CREST's feature-based routing is
  insufficient; consider cascade/verification approaches.

### 3.10 Acceptance criteria for "advance"

- CREST beats cost-aware by ≥10% on cost-per-success at signal ≥ 0.5, across
  ≥3 of 5 seeds, with overlapping CIs not excluding the difference.

### 3.11 What makes this inconclusive

- If the strong model is also unreliable (high failure rate), no strategy wins.
- If signal strength is too low, no routing strategy can work.
- If the cost ratio (5:1) doesn't reflect real pricing, cost conclusions are
  meaningless.

## 4. Leakage prevention

- Latent difficulty is never passed to any deployable strategy.
- Truth is never passed to any strategy.
- Calibration and evaluation sets are disjoint by construction.
- The oracle is reported separately and never mixed with deployable results.
- All strategies use the same evaluator (task truth) for scoring, but only after
  execution.
