## Additional work done toward V0.5 (verified this pass)
- Scope drift detection: `CrestRuntime.execute` re-checks that the target is
  still inside the admitted scope after the admission decision and revokes
  otherwise. Covered by `tests/security/test_runtime_guards.py`.
- Fail-closed execution-window guards: a capability that vanishes, or whose
  scope changes, between the admission decision and execution now denies,
  revokes, and audits instead of raising. Fixed and covered by
  `tests/security/test_runtime_guards.py`.
- Enhanced reproducibility package: `crest research reproduce` writes a
  schema-3 manifest recording python/crest versions, package versions, git
  commit and dirty-tree status, configuration file digest, raw source/table
  hashes, normalized scientific source/table hashes, and a `result_digest`
  that is stable across equivalent full runs. A separate
  `performance_digest` preserves run duration and wall-clock timing/latency
  observations. Covered by `tests/unit/test_reproduce_manifest.py` and
  `tests/unit/test_provenance.py`.
- Deep doctor diagnostics: `crest doctor --deep` cross-table invariant audit
  (orphan/revoked receipts, exposure budget, migration state, empty audit
  log, negative exposure rows). Covered by `tests/security/test_doctor_deep.py`
  and CLI exit-code tests in `tests/cli/test_cli_v0.py`.
- KeyProvider abstraction (`src/crest/signing.py`): `DevKeyProvider`
  (development) and `DeterministicKeyProvider` (test). The production HSM
  integration boundary is documented; no hardware-backed custody exists.
  Covered by `tests/security/test_key_provider.py`.
- Research reproduction gate: one canonical experiment configuration
  (`experiments/configs/experiment.yaml` via
  `experiments/generalization/config.py`) is the single source of truth for
  sample counts; the CLI, module defaults, and table provenance all resolve
  through it. Table regeneration is validated, staged, and gated on
  canonical configuration plus successful experiments; reduced
  (`--samples N`) runs are marked non-canonical and cannot replace canonical
  tables. Canonical `--full` passes no sample overrides, so each arm uses its
  own canonical value (20/8/6/3). Manifests record the experiment
  configuration, raw and normalized source hashes, and raw and normalized
  produced-artifact hashes. The complete canonical pipeline was executed
  twice on 2026-10-21; the scientific result digest was identical and the
  committed tables were regenerated with provenance headers. Covered by
  `tests/unit/test_experiment_config.py`,
  `tests/unit/test_evidence_prereqs.py`,
  `tests/unit/test_tables_integrity.py`,
  `tests/unit/test_reproduce_manifest.py`,
  `tests/unit/test_provenance.py`. See `docs/research-v0.4.md`
  ("Canonical configuration", "Reproducing this document") and
  `docs/final-autonomous-audit.md` §28.

## Remaining work for V0.5
- Probabilistic (seeded-random) sampling across families — not implemented
  (deterministic seed increments only).
- More environment families: the git family exists; database, container, and
  network families are not implemented.
- Production receipt key custody (HSM/KMS) and remote attestation — external
  infrastructure; not implemented and not simulated.
- Drift classes: environment drift not implemented; permission drift
  implemented (mode bits); scope drift implemented (see above).
- Composition verification as an admission gate — still measurement-only
  (`CrestRuntime.check_composition`); not enforced at admission.
- Multi-process exposure accounting: implemented with SQLite WAL +
  `BEGIN IMMEDIATE` (`Store.try_reserve_exposure`), single-host only; the
  two-process test passes (`tests/security/test_multiprocess_exposure.py`).
- Longitudinal evaluation against real agent workloads — not performed.
- Byte-identical research tables: the canonical n=20 pipeline has now been
  run end-to-end and the committed `experiments/tables/*` were regenerated
  with provenance headers. Scientific cells and normalized content hashes are
  stable across runs, but raw table bytes are not byte-identical because the
  timing/latency columns are wall-clock measurements. `result_digest` is
  stable; `performance_digest` and raw hashes are not. This limitation is
  documented rather than removed.

## Notes
- Permission drift: implemented in `_check_pinned_identity` (checks mode
  bits; any change revokes conservatively).
- Environment drift: not implemented; `src/crest/drift.py` documents the
  taxonomy and explicitly lists `ENVIRONMENT_DRIFT` as not yet implemented.
- Multi-process exposure: `BEGIN IMMEDIATE` ensures concurrent processes on
  the same state directory cannot both over-reserve. This is single-host
  SQLite coordination, not distributed consensus.
- Any claim of production key custody, distributed policy, or longitudinal
  reliability would be unjustified until the corresponding infrastructure
  exists; see `docs/final-autonomous-audit.md` for the full boundary.
