# V1.1 Adaptive Verification Experiment — Preregistered Protocol

Status: PRE-REGISTERED (written before any comparative result).

## Research question

Can a system reduce total verification cost by allocating verification effort
based on task uncertainty and risk, without reducing task success rate?

## Hypothesis

H1: Adaptive Verification (AV) achieves the same task success as "always verify
    at the highest tier" with lower total cost, by using cheaper verification
    tiers for low-uncertainty tasks.

H0: Adaptive Verification does not reduce total cost without reducing task success.

## Verification tiers

- **T0 (structural, cost 0.0):** JSON parse + required fields present + types correct.
  Catches: malformed JSON, missing fields, wrong types.
- **T1 (consistency, cost 0.1):** T0 + cross-field invariant check.
  Catches: T0 failures + internal inconsistencies.
- **T2 (semantic-cheap, cost 0.5):** T1 + cheap model judge ("does this look correct?").
  Catches: T1 failures + obvious semantic errors.
- **T3 (semantic-strong, cost 2.0):** T1 + strong model judge.
  Catches: all detectable errors (including subtle ones).

## Adaptive policy

1. Run the cheap model.
2. Run T0. If T0 fails → escalate to strong model (T3 on strong output).
3. If T0 passes, compute uncertainty estimate:
   - If task is in a class with historical failure rate > 0.1 → escalate to T2.
   - If T2 fails → escalate to T3 on strong model.
   - If T2 passes → accept (cost = cheap + T0 + T2).
4. If task is in a reliable class (historical failure rate ≤ 0.1) → accept
   after T0 (cost = cheap + T0).

## Baselines

1. **Always-T0:** Always accept after T0 (cheapest, least safe).
2. **Always-T3:** Always escalate to strong model with T3 verification (most expensive, safest).
3. **Fixed cascade:** T0 on cheap; if T0 fails, escalate to strong + T3.
4. **Adaptive Verification (AV):** As described above.

## Workload

Support-ticket extraction (4 fields, exact-match oracle). 100 calibration + 200 evaluation
tasks per seed. 5 seeds: 42, 123, 456, 789, 1024.

Model behavior: cheap model fails 20% on multi-topic tasks (semantic error:
wrong category value in valid JSON). Strong model always correct.

## Metrics

- Task success rate (exact match against gold).
- Total cost per task (model + verification).
- Cost per successful task.
- Verification tier distribution (how often each tier is used).
- Escalation rate.

## Success criteria

AV beats Fixed cascade on cost per successful task by ≥10% at equal success rate,
across ≥3 of 5 seeds.

## Failure criteria

If AV does not beat Fixed cascade, the experiment is a negative result. Document
why (e.g., verification tiers cannot distinguish error types) and recommend
whether to invest in better verification or abandon the direction.
