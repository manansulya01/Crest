# Crest V0.5 Claim-to-Evidence Inventory

This inventory was written from repository inspection at
`042ed7b703e7ffa3165d99136bfb262f64630b77`, before any V0.5 confirmatory
experiment. “Status” is the status of the existing evidence, not a new result.

## Scope boundary

CREST V0.4 is a **tool-capability admission controller**. Its “runtime” admits
filesystem, git, and shell operations only after recovery evidence is verified.
It is **not** an AI model inference control plane:

- there is no model adapter, model request/response type, token ledger, model
  verifier, or inference planner in `src/crest/`;
- `C6_general_cost_mean_seconds` and `C7_fixture_cost_mean_seconds` are
  wall-clock durations of synthetic verification loops;
- the research claims concern synthetic filesystem recovery, not model
  routing, provider latency, or monetary inference cost.

Any V0.5 model-runtime work must be presented as new infrastructure, not as a
validated extension of the V0.4 numbers.

## Immediate consequences for V0.5

1. Do not describe V0.4 cost numbers as model or monetary cost.
2. Do not claim drift coverage beyond what the canonical experiment actually
   demonstrates; fix or narrow the drift claim before using it as a runtime
   guarantee.
3. The V0.5 inference runtime must be evaluated separately with deterministic
   fake adapters. Its budget and verification invariants must be tested
   independently of the V0.4 recovery tables.
4. The independent validation should test the **decision policy** on a fresh
   candidate set, not merely re-run the same seeds and call that independent.
