## 6. Comparative results

### Fake pilot (deterministic, mode=fake)

| strategy | success | est. USD | input tok | output tok | retries |
|---|---|---|---|---|---|
| fixed_large | 1.00 | 0.0006 | 1083 | 248 | 0 |
| cost_aware_small | 0.90 | 0.0002 | 1083 | 249 | 0 |
| crest_policy | 1.00 | 0.0006 | 1083 | 248 | 0 |

- CREST degenerates to `fixed_large` at this calibration size: 30 calibration tasks,
  zero observed failures, Wilson upper bounds 0.1095 (single-topic) and 0.2527
  (multi-topic), both above the 0.05 admission threshold. No admission → no routing
  to the cheap model → no cost advantage.
- `cost_aware_small` is cheaper but 10 points less accurate.

### Live pilot (mode=live, strong model unavailable)

- Strong model `gemini-3.8-flash`: HTTP 503 on the health probe and on every
  retry (bounded to 3 attempts) → recorded as NOT_RUN (20 not-run rows), no silent
  model switching.
- Cheap model `gemini-3.5-flash-lite`: 10/10 pilot tasks correct with the system
  prompt wired; 4 transient retries; 1685 input / 311 output tokens; est. USD 0.0003.
- CREST: 10 NOT_RUN rows (no admission at this calibration size, and the large
  model is unavailable), so CREST did not execute on any pilot task.

## 9. Whether the success criterion was met

NO. Pre-registered target: ≥20% lower cost than fixed_large with ≤2pp success loss,
no budget violations, reproducible. CREST did not achieve lower cost (it equaled
fixed_large in fake mode; it did not run in live mode). Budget/retry invariants
held (no silent violations). Reproducibility holds for fake mode (summary and
rows identical aside from timing).

## 10. What the evidence supports — and what it does not

Supports:
- The CREST inference runtime executes a real structured task end to end against a
  live provider with provider-reported usage and a consistent ledger.
- The measurement pipeline (identical inputs, shared validation, exact-match oracle,
  per-strategy rows, machine-readable artifact) works and is reproducible.
- On this workload the cheap model is sufficient (100% live success), so the
  routing problem is trivial here and CREST adds no cost advantage.
- CREST's strict admission rule correctly refuses to admit on small calibration
  samples (Wilson bounds too wide) rather than over-claiming.

Does not support:
- Any claim that CREST lowers inference cost on this workload.
- Any claim about the strong model's quality (it was unavailable).
- Any real-world/customer-traffic conclusion (synthetic data only).
- Any claim about held-out performance (held-out set was not touched).

## 11. Recommended next decision

NARROW. The advantage, if any, only appears where cheap models fail on a
measurable subset of tasks. The pilot shows this workload is too easy for the
cheap model, and the admission rule needs ~50+ calibration examples per class
before it can admit. Next test: a harder workload with a measurable cheap-model
failure rate on a distinct subset, using the same harness. If that also shows no
advantage, pivot/stop. Held-out remains sealed until a workload that exercises
routing is identified.

## Sprint 3 Addendum � Calibration Split Enlarged (2026-10-27)

After the admission-math audit (docs/v0.8-evidence-audit.md) showed that the
Wilson upper bound cannot reach 0.05 below ~52 calibration successes per class,
the calibration split was enlarged from 30 to 120 tasks (held-out remains 100,
pilot remains 10; seed unchanged at 20261025). This is a design correction
identified by the audit, not a change to the pre-registered success criterion.

### Fake pilot result (enlarged calibration, mode=fake)

| strategy | success | est. USD | input tok | output tok |
|---|---|---|---|---|
| fixed_large | 1.00 | 0.0006 | 1071 | 244 |
| cost_aware_small | 0.90 | 0.0002 | 1071 | 245 |
| crest_policy | 1.00 | 0.0003 | 1071 | 244 |

Calibration (120 tasks): single_topic 77 tasks, 0 failures, upper bound 0.0339
(= 0.05 ? admitted). multi_topic 43 tasks, 4 failures, upper bound 0.1918
(> 0.05 ? not admitted).

CREST now routes single-topic tasks to the cheap model and multi-topic tasks to
the strong model, achieving 50% lower estimated cost than fixed_large at equal
success (1.00). This is a genuine routing advantage in fake mode. It remains
fake-mode evidence (simulated model behavior); the live strong model is
unavailable (read timeout), so no live verification exists.
