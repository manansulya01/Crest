# What CREST currently does (and does not do)

## What it does

- Maintains a separate, auditable model-inference runtime (`src/crest/inference.py`)
  with policy enforcement: model allowlists, token/character limits, abstract
  cost units, window budgets, and conservative reservation (never refunded).
- Executes real OpenAI-compatible provider calls (verified end to end against
  `gemini-3.5-flash-lite`) and records provider-reported usage, attempts,
  retries, errors, and validation outcomes in a SQLite ledger.
- Retries transient failures (timeouts, network errors, HTTP 429/500/502/503/504)
  with a bounded attempt count and optional backoff.
- Represents unknown provider usage honestly (`cost_known=False`) instead of
  silently recording zero.
- Provides a benchmark harness with identical inputs across baselines, exact-match
  oracle scoring, machine-readable artifacts, and a hard budget guard.

## What it does not do

- It does not lower inference cost on the tested workload: the cheap model was
  sufficient (100% success) on support-ticket extraction, so there was no
  quality gap for routing to exploit.
- It does not claim novelty or real-world validation: the dataset is synthetic and
  labeled as such; the live strong model was unavailable (HTTP 503) during the
  pilot, so no live strong-baseline comparison exists.
- It does not perform autonomous agent orchestration, online learning, or
  multi-stage workflows.
- It does not expose inference commands via the CLI (Python API only).
- It does not provide authoritative USD cost (only provider-reported usage plus
  unverified price assumptions).

## Evidence status

- Live provider: PARTIAL (cheap model PASS; strong model NOT RUN).
- Held-out evaluation: NOT RUN (sealed pending a workload that exercises routing).
- Success criterion (≥20% lower cost, ≤2pp success loss): NOT MET on this workload.
