# Simulation Circularity Audit — Sprint 3

## Finding

The fake-mode 50% cost advantage reported in Sprint 1/Sprint 2 is **not evidence of
a genuine controller capability**. It is a circular artifact of the simulator design.

### Mechanism of circularity

1. `experiments/benchmark/tasks.py::derive_features` computes `multi_topic` from
   the task text (line ~153): `multi_topic = second_topic is not None`, where
   `second_topic` is detected by keyword matching in the task's remainder text.

2. `Task.multi_constraint` is set to `features.multi_topic` (line ~227):
   `multi_constraint=features.multi_topic`. So the routing feature and the task's
   "difficulty" flag are the **same boolean**.

3. `FakeTaskModelAdapter.complete` (adapters.py, line 86) fails **only** when
   `task.multi_constraint` is True AND `sha256(task_id) % 5 == 0`:
   ```python
   if self._cheap and task.multi_constraint:
       if int(hashlib.sha256(task.task_id.encode()).hexdigest()[:8], 16) % 5 == 0:
           ... flip category to distractor ...
   ```

4. The CREST admission policy routes based on `capability_of(task)`, which calls
   `derive_features(task.text)` → `multi_topic` → the **same boolean** that
   determines whether the fake model can fail.

### Consequence

The routing feature perfectly predicts which tasks the fake cheap model can fail
on (the multi-topic class). The controller's "advantage" reduces to: "route to
the cheap model only on tasks where the simulator guarantees the cheap model
will not fail." This is trivially achievable and does not demonstrate that the
controller can predict model failure from task characteristics in any realistic
setting.

### What the result actually shows

- The admission rule correctly refuses to route to an unreliable class (multi_topic,
  21.7% failure rate, upper bound 0.2844 > 0.05).
- The admission rule correctly admits a reliable class (single_topic, 0% failure,
  upper bound 0.0339 ≤ 0.05) when given ≥52 calibration samples.
- The harness, budget guard, and measurement pipeline work correctly.

### What the result does NOT show

- That CREST can predict model failure from task features in a non-circular setting.
- That the advantage persists when features are imperfect predictors of failure.
- Any live-provider result (the strong model is unavailable).

### Corrective action

The 50% fake-mode saving must not be cited as evidence of a genuine controller
capability. It should be described as: "a simulation in which the routing feature
perfectly predicts the failure mode, demonstrating the mechanism but not its
real-world validity."

A non-circular simulation must use an independent (noisy) failure signal that
the routing feature can only imperfectly predict. This is the next required
experiment before any advantage claim.

### Retained value

Despite the circularity, the following are genuinely demonstrated:
- The inference runtime works end to end (live, with provider-reported usage).
- The budget guard, retry logic, and unknown-cost tracking are functional.
- The admission policy's statistical behavior is correct and independently
  verified (Wilson bound, minimum sample size ~52).
- The measurement pipeline is reproducible and auditable.
- The calibration-split enlargement (30 → 120) was a justified design correction
  based on mathematical analysis, not post-hoc tuning.
